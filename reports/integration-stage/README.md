# Проверка телеметрии и первого агента

Этот отчёт описывает проверку до подключения ArduSub. Результаты последующего совместного запуска находятся в [ardusub-stage](../ardusub-stage/README.md).

Проверка выполнена на учебной модели Stonefish 1.6 в Docker Linux ARM64 с ROS2 Humble и Python 3.10. В течение 25 секунд подавались команды прямого движения, поворота, реверса и вертикальной тяги. Идентификатор запуска: integration-84b3608ccb0a.

Получена 251 запись телеметрии, показания давления, IMU, DVL, навигационной одометрии и отдельного истинного состояния. Из данных сформированы пять окон по 5 секунд и пять JSON-сводок первого агента. Все проверки в verification.json прошли. Количество сообщений отдельных источников указано в source_counts.

Наблюдаемые обороты находились в диапазоне от -1336,22 до 1909,74 об/мин. Знак менялся при реверсе. Сохранены последняя отправленная команда, нормированное применённое задание и внутреннее задание в рад/с. Истинное положение записано отдельно в evaluation_ground_truth.json.

На записанных сообщениях проверены пять режимов доставки. В нормальном режиме принята 251 из 251 записи, средняя задержка 100 мс. При заданной задержке 700 мс получено измеренное среднее 700 мс. В запуске со случайными потерями принято 202 из 251 записи, фактические потери 19,52%. Отключение виртуального отправителя и разрыв соединения вызвали тайм-аут недоступности и событие восстановления после появления новых сообщений. Это программное воспроизведение доставки, без отключения реального процесса и без модели акустического сигнала.

21 тест прошёл на Mac и в контейнере Python 3.10. Тесты проверяют форматы, преобразование осей, знаки и масштаб RPM, пропуски, устаревшие измерения, тайм-аут, восстановление, дубликаты и независимость отправителей. Это проверки программной части. Они не являются 40 диагностическими сценариями из ТЗ.

## Подтверждающие файлы

- verification.json: проверки сцены и счётчики источников.
- telemetry_window_1.json: вход первого агента из реального запуска.
- monitoring_summary_1.json: соответствующая сводка.
- commands.json: отправленные команды.
- evaluation_ground_truth.json: истинная траектория для оценки.
- network_*.json: наблюдаемые итоги сетевых проверок.
- unittest.txt: журнал проверки Python на Mac.
- colcon-test.txt: 21 тест установленного ROS2-пакета в пересобранном контейнере.
- ros2_smoke_summary.json: результат повторной проверки прежней цепочки четырёх узлов на 20 сообщениях.
- SOURCE_SHA256SUMS.txt: контрольные суммы исходников, использованных для этого этапа.

## Ограничения

Навигационная оценка имитируется одометрией с шумом. Объединение показаний датчиков не реализовано. Для DVL используется ограниченная проверка по доступности расстояния до дна. Время сообщений берётся из часов ROS, а не из отдельного счётчика физического решателя.

LLM, RAG и ArduSub не подключены. Независимый прогноз ожидаемой траектории и 40 сценариев распознавания неисправностей ещё предстоит реализовать. Точность диагностики на этом этапе не рассчитывается.

Команды повторения и поля сообщений: [../../docs/stonefish-integration.md](../../docs/stonefish-integration.md).
