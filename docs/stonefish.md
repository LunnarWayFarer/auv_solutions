# Проверка датчика давления Stonefish

Проверка выполняется на Linux ARM64 и получает показания датчика Stonefish через ROS2. Сценарий `scenarios/pressure_probe.scn` содержит неподвижную сферу на глубине 5 метров и датчик давления 10 Гц. Сценарий используется для проверки датчика и передачи данных. Модель АНПА и неисправности добавляются на следующем этапе.

## Сборка и запуск

Из корня проекта при работающем Docker Desktop:

```sh
docker build -f docker/Dockerfile -t auv-week1 .
docker build -f docker/Dockerfile.stonefish -t auv-stonefish .
mkdir -p artifacts
docker run --rm --mount type=bind,source="$PWD",target=/host auv-stonefish python3 /host/scripts/check_stonefish.py --scenario /host/scenarios/pressure_probe.scn --output-root /host/artifacts
```

Первая сборка загружает C++/PCL-зависимости и требует существенно больше места, чем базовый образ. После изменений только сценария или проверочного скрипта пересборка не требуется: эти файлы передаются через bind mount.

При успехе скрипт печатает `STONEFISH_SMOKE_PASS`. Проверяется получение 10 сообщений `sensor_msgs/msg/FluidPressure` на `/probe/pressure`, диапазон давления 40-60 кПа для заданной глубины и увеличение временных меток. В `artifacts/stonefish-*/` сохраняются `simulator.log`, `pressure.jsonl` и при успешной проверке `summary.json`. Ошибка/тайм-аут даёт ненулевой код; процесс симулятора завершается после проверки.

Источник публикует манометрическое давление. Для этого стенда ожидаемое давление составляет ρgh ≈ 50.6 кПа. Диапазон проверки намеренно широкий: он обнаруживает ошибку масштаба/глубины, но не заменяет верификацию физики.

## Закреплённые исходники и поправка Humble

- Stonefish 1.6: `b21eb8e194c570ff2f61e91aeffb38d73dc25f42`.
- stonefish_ros2 1.6: `6646e7ac25eed982f37f807abc7b545dbd2d6648`.
- `docker/patch_stonefish_humble.py` исправляет одно выражение в `ROS2Interface.cpp`: перед сложением с `rclcpp::Duration` поле `msg.header.stamp` преобразуется в `rclcpp::Time`.

Без поправки эта ревизия моста не компилируется на проверенном Humble: для `builtin_interfaces::msg::Time + rclcpp::Duration` отсутствует подходящий оператор. Поправка относится к функции публикации событий камеры; её реальное поведение на камере не тестируется headless-сценарием. Скрипт требует ровно одно совпадение исходного выражения и останавливает сборку при изменении upstream.

## Доступ к пакетам

В проверенной сети HTTP-загрузки пакетов не работали, а HTTPS на `packages.ros.org` возвращал сертификат с несовпадающим именем. Ubuntu-пакеты загружаются по HTTPS; для ROS используется зеркало Tsinghua, указанное в [официальной документации зеркал ROS](https://docs.ros.org/en/rolling/Installation/ROS-2-Mirrors.html). Проверка TLS и подписи apt включены. Индекс `deb-src` отключён, поскольку зеркало не предоставило его, а установка бинарных зависимостей его не требует.

Для другого окружения адрес можно задать параметром `--build-arg ROS_APT_URL=...`. Зеркало должно предоставлять подписанные ROS-пакеты. Проверка подписей остаётся включённой.

## Границы проверки

- Визуализация, камера, сонар, движители и ArduSub не проверяются.
- Показания давления пока не подключены к тестовому формату диагностических данных. Следующий адаптер должен принимать реальные измерения и явно отмечать отсутствие остальных сигналов.
- Подключение LLM/RAG отсутствует.
- Текущий тест не оценивает точность диагностики и не подтверждает работу подводной сети.
