# Форматы телеметрии и тестового отчёта

Текущий формат имеет версию `0.1`. В ROS2 используется сообщение `std_msgs/msg/String` с JSON внутри. Формат подходит для синтетического источника из этого пакета. Он пока не описывает сообщения Stonefish или MAVLink.

## Общие поля

- `schema_version`: строка `"0.1"`.
- `run_id`: непустой идентификатор запуска.
- `vehicle_id`: непустой идентификатор аппарата.
- `sequence`: целый неотрицательный номер сообщения.
- `stamp_sec`: неотрицательное конечное число.

Идентификаторы и номер сообщения сохраняются после обработки. В синтетическом источнике `stamp_sec` равен номеру сообщения. Это условная модельная шкала, а не системное время и не время ROS `/clock`. Сообщения публикуются с частотой 5 Гц, но поле времени этого источника не соответствует шагу 0,2 с.

Проверка отклоняет отсутствующие и лишние поля, числа в строках, NaN, Infinity и дубли ключей JSON. Логические значения не принимаются вместо чисел.

## Исходная телеметрия

Топик `/telemetry/raw` содержит общие поля и три показания:

- `depth_cm`: неотрицательная глубина в сантиметрах, направление вниз.
- `speed_cm_s`: неотрицательный модуль скорости в сантиметрах в секунду.
- `thruster_command_pct`: условная команда движителю от -100 до 100 процентов.

Команда движителю не является измерением оборотов или тяги. Данных о координатах и ориентации здесь нет.

## Преобразованные данные

Топик `/telemetry/normalized` содержит общие поля и:

- `source`: строка `"synthetic"`.
- `depth_m`: глубина в метрах, исходное значение делится на 100.
- `speed_m_s`: скорость в метрах в секунду, исходное значение делится на 100.
- `thruster_command`: команда от -1 до 1, исходное значение делится на 100.

Текущий валидатор принимает только источник `synthetic`. Для данных Stonefish потребуется отдельный адаптер и согласованный формат частичных показаний. Преобразования координат NED/ENU пока не выполняются.

## Тестовый диагностический отчёт

Топик `/diagnostics/report` сохраняет общие поля. Остальные поля:

- `status`: `"stub"`.
- `anomaly_type`: `"unknown"`.
- `agent`: `"fixed-stub/0.1"`.
- `evidence`: глубина, скорость и команда движителю после преобразования.
- `recommendations`: список с сообщением о тестовом режиме.
- `rag_references`: пустой список.

Такой ответ не определяет неисправность и не подтверждает нормальную работу. Валидатор отчёта специально ограничен тестовым ответом. Перед подключением диагностического агента его нужно расширить.

## Ошибки и доставка

При некорректном входе адаптер и тестовый диагностический узел записывают ошибку в журнал ROS2 и топик `/diagnostics/status`, после чего продолжают принимать данные. Узел записи проверяет отчёт, игнорирует сообщения другого запуска и не записывает повторные номера.

Для ограниченного запуска используется QoS `reliable`, `transient_local`, глубина очереди 100. Это позволяет принять историю поздно запущенным подписчикам. Количество сообщений ограничено сотней. QoS датчиков Stonefish проверяется отдельно.

Все узлы демонстрации используют общие имена топиков. Параллельным запускам в одной сети нужны разные `ROS_DOMAIN_ID` или дальнейшая настройка пространств имён.
