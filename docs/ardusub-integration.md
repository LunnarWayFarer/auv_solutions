# Stonefish, ArduSub и первый агент

Stonefish рассчитывает движение аппарата и показания датчиков. ArduSub SITL получает состояние симуляции, обрабатывает команды движения и выдаёт PWM для четырёх движителей. ROS2 связывает эти процессы со сборщиком телеметрии. Первый агент раз в пять секунд сохраняет JSON-сводку и публикует её в ROS2.

Диагностическая LLM и RAG пока не подключены. Проверка этого этапа подтверждает обмен данными и управление движителями. Точность распознавания неисправностей здесь не измеряется.

## Как проходит обмен

1. Stonefish публикует IMU, DVL, давление, одометрию и состояние движителей.
2. `ardusub_bridge.py` передаёт в JSON backend ArduSub время физического расчёта, угловую скорость, ускорение, положение, скорость и ориентацию корпуса.
3. ArduSub возвращает UDP-пакеты с PWM. Мост преобразует первые четыре канала в команды от -1 до 1 и публикует `/auv_01/thruster_command`.
4. Stonefish рассчитывает вращение роторов и движение корпуса. В `/auv_01/thruster_state` появляются фактические для этой модели RPM, тяга и момент.
5. `ardusub_mavlink.py` читает MAVLink и публикует состояние автопилота в `/auv_01/autopilot/telemetry`.
6. Сборщик формирует пятисекундные окна `/auv_01/telemetry_window`. Первый агент проверяет их, рассчитывает признаки и публикует `/auv_01/monitoring_summary`. В обоих топиках используется `std_msgs/msg/String` с JSON внутри.

Для связи с физическим движком используется UDP 9002. MAVLink читается через TCP 5760. В проверочном контейнере эти порты доступны только внутренним процессам; публикация портов на Mac не требуется.

## Движители и единицы

Первые четыре выхода ArduSub соответствуют левому горизонтальному, правому горизонтальному, переднему вертикальному и заднему вертикальному движителю. В исходниках ArduSub для `FRAME_CONFIG=7` добавлена схема `PROJECT2600_4`, которая соответствует расположению движителей в `integration.scn`. Изменение вынесено в `docker/patch_ardusub_mixer.py`; остальные штатные схемы сохранены.

PWM 1500 мкс соответствует остановке, 1100 мкс даёт команду -1, 1900 мкс даёт +1. Нулевой выход неактивного канала преобразуется в остановку. Значения вне этих пределов отклоняются. Перевод PWM в нормированную команду задаёт модель исполнительного устройства для этой учебной сцены. Для другого движителя потребуется своя характеристика PWM, оборотов и тяги.

Команда движения `MANUAL_CONTROL` проходит через настройки усиления ArduSub, затем через его схему смешивания. Она не равна команде отдельному движителю. Для проверки используется режим MANUAL; удержание глубины, курса и автономный маршрут пока не проверялись.

RPM берутся из Stonefish, в об/мин. Они могут быть отрицательными при реверсе. MAVLink `SERVO_OUTPUT_RAW` содержит PWM в мкс и не используется как измерение RPM.

## Время и координаты

В образе добавлена публикация `/stonefish/physics_time` типа `std_msgs/msg/Float64`. Источник времени находится в физическом решателе Stonefish. Этот топик нужен JSON backend ArduSub и не заменяет системные часы ROS.

Мост передаёт положение в NED и ускорение с угловой скоростью в системе корпуса FRD. Скорость из одометрии Stonefish задана в системе корпуса: перед отправкой мост поворачивает её в мировую NED. Порядок компонент кватерниона меняется с ROS x,y,z,w на ArduPilot w,x,y,z. Показание акселерометра уже содержит вычитание гравитации; повторно вычитать её нельзя.

Окна первого агента по-прежнему используют часы ROS, `clock_domain=ros_wall`. Состояние из нескольких топиков собирается асинхронно, с контролем свежести. Это не строгий пошаговый обмен двух решателей: в ArduSub отключена дополнительная подстройка скорости по внешнему времени (`no_time_sync=true`), а тип оценки ориентации закреплён параметром `AHRS_EKF_TYPE=3`.

Истинная одометрия поступает в мост физического состояния SITL и сохраняется для оценки. Она не включается в JSON первого агента. Навигационные признаки первого агента пока рассчитываются по отдельной одометрии Stonefish с заданным шумом. Подключение оценки навигации ArduSub и её проверка требуют следующего этапа.

## MAVLink

DVL и давление Stonefish сейчас поступают первому агенту. В JSON backend автопилота передаются IMU и состояние корпуса; барометры MAVLink формирует сам SITL по этому состоянию. Передача DVL в оценку навигации ArduSub и отдельного показания давления Stonefish в его драйвер датчика пока не реализована.

В проверенном запуске получены:

- `HEARTBEAT`: состояние, режим и признак разрешения работы движителей.
- `ATTITUDE`: углы в радианах, угловая скорость в рад/с.
- `SCALED_PRESSURE` и `SCALED_PRESSURE2`: исходные давления в гПа. В поле `normalized` они переводятся в Па умножением на 100. Номер датчика сохраняется. Глубина по этим сообщениям пока не рассчитывается: необходимо проверить назначение барометров и опорное давление.
- `SERVO_OUTPUT_RAW`: выходы каналов в мкс.

Для каждого сообщения сохраняются исходные поля, преобразованные значения и возраст сообщения. Внешний возраст всего состояния находится в `receiver_age_s`.

Для `LOCAL_POSITION_NED` подготовлены запрос и преобразование полей, но в проверенном запуске сообщение не поступило. В текущей конфигурации имитируемый GPS отключён. Оценку положения ArduSub нельзя считать подключённой только по наличию обработчика сообщения.

## Обработка остановки обмена

Если новые UDP-пакеты от автопилота не приходят 0,5 секунды, мост публикует нулевые команды. То же происходит, если IMU, истинная одометрия или время физического расчёта устарели более чем на 0,3 секунды. Повторный или старый номер UDP-пакета не продлевает время действия команды. При перезапуске ArduSub нужно перезапустить всю связку, поскольку мост ожидает возрастающий номер кадра.

В итоговой проверке ArduSub останавливается при продолжающейся работе Stonefish. Проверяются нулевые команды, срабатывание тайм-аута и дальнейшее увеличение времени физического расчёта. Защита действует, пока сам мост продолжает работать. Остановка моста отдельным процессом пока не проверяется; у подписчика Stonefish ещё нет собственного тайм-аута команд.

## Сборка на Mac

Потребуется работающий Docker Desktop. Все команды выполняются из корня исходников. Первая загрузка исходников ArduSub и сборка занимают больше времени, чем повторный запуск. Исходники сторонних компонентов остаются в `artifacts/` и не входят в Git проекта.

Если образы Python/ROS2 и Stonefish ещё не собраны, сначала выполните команды из `stonefish.md`. Затем:

```sh
bash scripts/fetch_ardusub.sh
docker build --build-context ardupilot_source=artifacts/ardusub-source -f docker/Dockerfile.ardusub -t auv-ardusub .
```

Закреплена версия ArduSub 4.7.2, commit `fb773567896014da007bca58358704d4a0d8516f`. Скрипт подготовки проверяет commit и разрешает передачу исходников в Docker: исходный `.dockerignore` ArduPilot исключает файлы, нужные для этой сборки.

## Совместная проверка

```sh
docker run --rm --mount type=bind,source="$PWD",target=/host auv-ardusub python3 /host/scripts/check_ardusub_integration.py --output-root /host/artifacts
```

Проверка сама запускает Stonefish, мост физического состояния, ArduSub, приём MAVLink и первый агент. Она разрешает работу движителей в SITL, выполняет движение вперёд, реверс, поворот и вертикальную команду, затем останавливает ArduSub. Команды действуют только внутри программной симуляции. Параметры `scenarios/ardusub.parm` предназначены для этого запуска.

Успешный запуск печатает `ARDUSUB_STONEFISH_PASS`. В новой папке `artifacts/ardusub-*/` находятся:

- `verification.json`: результаты всех проверок; значения `checks` должны быть `true`.
- `bridge.jsonl` и `bridge_summary.json`: принятые PWM, номера кадров и счётчики обмена.
- `mavlink.jsonl` и `mavlink_summary.json`: телеметрия, ответы на команды и результаты последовательности движения.
- `observed_monitoring_summaries.json`: пять сводок, полученных отдельным подписчиком через ROS2.
- `integration-*/`: показания, окна JSON, сводки, отдельная истинная траектория и проверки нарушений доставки.

Последние сетевые проверки выполняются на записанных сообщениях. Проверка остановки ArduSub выполняется на работающих процессах. Модель акустической связи и обмен нескольких аппаратов на этом этапе не добавлены.

Проверки без симуляции:

```sh
PYTHONPATH=ros2_ws/src/auv_diagnostics python3 -m unittest discover -s ros2_ws/src/auv_diagnostics/test -v
.venv/bin/ruff check ros2_ws/src scripts docker/patch_ardusub_mixer.py docker/patch_stonefish_clock.py
```
