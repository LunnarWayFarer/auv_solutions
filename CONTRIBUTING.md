# Работа с кодом

Изменения готовятся в отдельной ветке от актуальной основной ветки общего репозитория. Для этой программной части можно использовать ветку `feature/ros2-integration`.

Изменение формата данных должно сопровождаться обновлением обработки, описания полей и тестов. Перед передачей кода выполняются Ruff и unittest из README. После изменения ROS2-узлов или launch-файла также нужны сборка контейнера, `colcon test` и проверка передачи сообщений.

В описании Pull Request указываются изменения, выполненные проверки и ограничения. Подготовленный workflow не считается успешным запуском GitHub Actions: результат станет известен после его выполнения в общем репозитории.

В исходный код не включаются виртуальное окружение, результаты сборки ROS2, Docker-образы, веса моделей и крупные записи телеметрии. Выбранные небольшие результаты проверок можно хранить в `reports/`. Остальные файлы запусков сохраняются в `artifacts/` и исключены из Git.
